## Организация кода

task-service.js - логика над массивом задач. не знает про DOM, формы и localStorage. возвращает { ok: true, tasks } или { ok: false, error }.  
form-validation.js - функция validateTaskDraft, проверяет черновик формы. возвращает { ok: true, value } или { ok: false, errors }. Не обращается к DOM.  
task-storage.js - читает и пишет JSON в localStorage. все операции обернуты в try/catch. проверяет схему перед использованием через isValidTaskList.  
task-view.js - создает DOM-карточки, обновляет список, сводку и пустые сообщения. не изменяет данные и не сохраняет в хранилище.  

Почему storage передаётся аргументом: для тестируемости. В modules.checks.js передаётся MemoryStorage - имитация localStorage. Без аргумента пришлось бы обращаться к глобальному window.localStorage, который в Node.js недоступен.  
Почему данные из JSON проверяются: успешный JSON.parse ещё не значит, что данные правильные. Там может быть массив с повторяющимися id, строки вместо boolean, неверные приоритеты. Без проверки приложение упадёт или покажет некорректный список.  

main.js - связывает все: слушает события формы и карточек, вызывает сервис, вызывает хранилище, перерисовывает UI.

## Отладка и клавиатура

- **Точка останова в `handleFormSubmit`** на строке `const validation = validateTaskDraft(...)`:  
  - `draft` = `{ id: "20", title: "  Изучить localStorage  ", priority: "high" }` (все строки!)  
  - `validation.value` = `{ id: 20, title: "Изучить localStorage", priority: "high" }`  
  - `result` от `addTask` = `{ ok: true, tasks: [...] }`  
  - JSON-строка в storage: `{"version":1,"tasks":[...]}`  

- **Клавиатура:** Tab проходит по полям формы. Enter в любом поле инициирует `submit`. После отправки фокус возвращается на поле `id`. При нажатии «Изменить» фокус переходит на поле `title`. При отмене - на `id`. Space активирует кнопки фильтра.

## Вывод

В ПР4 приложение стало полностью функциональным: добавление, редактирование, удаление, фильтрация, статус и сохранение между перезагрузками работают вместе. Основная работа - разграничить три уровня проверки:  

1. **Нативный (HTML):** `required`, `min`, `maxlength`. Быстро, но не знает правил модели и не отклоняет строки из пробелов.  
2. **Прикладной (`validateTaskDraft`):** точные правила - уникальность `id`, `trim()`, длина, приоритет. Чистая функция, не работает с DOM.  
3. **Схема хранения (`isValidTaskList`):** данные после `JSON.parse` проверяются целиком. Если что-то не так - отказ и fallback.  

Также исправлено несколько ошибок: `throw` в `getVisibleTasks` заменён на рабочий фильтр; в `task-view.js` исправлена `ReferenceError` (переменная `actions` заменена на `actionsDiv`); в `data.js` удалён отладочный вызов, ломавший импорты; в `task-storage.js` введён экспорт `STORAGE_VERSION = 1`; в `task-service.js` добавлено обрезание пробелов `trim()` в `createTask` и `renameTask`.
